# 本地数据保护 Implementation Plan

> 用户要求保护客户电脑上的对话数据，不部署服务。本次由当前 agent 直接实现并验证。

**Goal:** SQLite 原子持久化项目、对话及历史，旧数据无损迁移，自动备份可恢复为副本。
**Architecture:** 每项目 userData/projects/<id>/project.sqlite 保存完整 metadata 与 Loro 快照，单事务提交，FULL 同步；原 JSON/Loro 保留为兼容镜像，导入导出沿用现有格式。SQLite 不存 API 密钥。备份包含数据库内容，附件保留在项目 files；换电脑使用完整项目导出。
**Spec:** specs/0002-desktop-client-spec.md 本地持久化与升级保护。

- [x] 存储层：真 SQLite 测试迁移、事务失败回滚、备份/恢复、未来 schema 拒绝；逐操作关闭数据库以支持 Windows 回收站。
- [x] 项目接入：以 DB 为准，旧文件校验后迁移、移除 400 条和 50 会话截断；同版本不同构建也备份。
- [x] 设置 → 项目数据：显示数据路径、手动备份、查看备份、恢复为新副本，不覆盖原项目。
- [ ] 验证：重启、模拟覆盖升级、超过历史限制、导入导出、损坏数据库恢复、单元/typecheck/完整 E2E。
- [ ] 交付：隔离其他进行中的修改，PR / CI / 更新步骤与前次交付一致。

约束：安装包目录与 userData 分离；Windows 卸载默认不删除本地数据。日备份保留 7 份，升级备份 5 份，手动备份 5 份，初次迁移备份保留。已删除的外部附件不能仅靠数据库备份恢复；完整项目导出包含附件。尚未保存的输入和生成中尚未收到的文字不承诺恢复。


审阅与验证记录：
- 主库必须以可写模式打开来恢复崩溃留下的 hot journal；新增子进程 SIGKILL 真事务回归，验证精确恢复已提交字节。
- 备份通过临时文件、校验、fsync 与原子重命名发布；残缺日备份重建，临时文件不列入可恢复列表。
- 恢复副本保留原 AI 撤销历史；回收站以 SQLite 为准，兼容镜像缺失不隐藏项目。
- 真 Electron 迁移 450 条消息、60 个历史会话，覆盖更新、损坏镜像修复、损坏主库恢复、附件复制、SQLite-only 回收站均通过。

- Windows CI 揭示只读文件描述符不能 fsync，备份改用可写描述符；首轮活动 UI 测试等待界面订阅后才放行假服务流，消除初始化速度变化引起的时序失败。
- 发送用户提问后立即持久化，再调用远端模型；新增生成等待中重启仍保留提问的 Electron 测试。
