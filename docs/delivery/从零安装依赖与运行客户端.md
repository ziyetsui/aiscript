# Ancher Scripter：从零安装依赖与运行客户端

适用版本：本仓库 `1.0.0-beta.3`。本文面向一台尚未安装开发工具的新电脑，分别说明安装包使用、源码运行和自行打包。后续版本以仓库中的 `package.json`、`pnpm-lock.yaml` 和发行者提供的安装包说明为准。

## 1. 先选择安装方式

| 你拿到的内容 | 按哪条路线操作 | 需要自己安装开发依赖吗 |
| --- | --- | --- |
| macOS 的 `.dmg`，或 Windows 的 `setup.exe` | 第 2 节：安装包使用 | 不需要，运行组件已打包 |
| GitHub 仓库访问权限，需要从源码运行 | 第 3–7 节：源码运行 | 需要 Git、Node.js、pnpm，以及项目依赖 |
| 需要制作安装包发给其他客户 | 完成源码运行后继续第 8 节 | 需要对应平台的打包工具与发行者授权配置 |

普通客户优先使用发行者交付的安装包。客户端包含 Electron 运行环境、FFmpeg、YouTube 下载工具 yt-dlp 和 Deno；React、Ancher SDK、Mastra、Loro 等程序依赖也随包交付。无需额外安装 Python、Docker、数据库服务器、Mastra 服务或本地大模型。

本文支持的打包目标为 Apple 芯片 Mac、Intel Mac 和 Windows x64。Windows ARM、Linux 未列入当前交付目标。操作系统兼容性和各平台实际验收结果，以本次交付的验收记录为准。

## 2. 路线 A：安装包使用

### 2.1 准备文件与账号

请向发行者取得以下内容：

1. 与电脑平台匹配的安装包，以及该文件的 SHA256 校验值。
2. 本机机器码对应的客户端激活码；首次安装后才能取得机器码。
3. 自己的 Ancher 账号及 API key，用于 AI 写作、联网搜索和 Ancher 笔记。
4. 如需本地音视频转写，再准备 Gemini API key：Google AI Studio 或支持 API-key 请求的 Google Cloud 配置，二选一。

客户端激活码、Ancher API key、Gemini API key 是三种不同凭据。安装并激活客户端不等于已经连接 AI 服务。

### 2.2 macOS 安装

1. 点击苹果菜单 →「关于本机」。显示 Apple M 系列芯片时选 `mac-arm64.dmg`；显示 Intel 处理器时选 `mac-x64.dmg`。
2. 打开 `.dmg`，将 **Ancher Scripter** 拖到「应用程序」文件夹。
3. 完成复制后弹出磁盘镜像，从「应用程序」启动应用。
4. 若系统提示来源或签名问题，先核对发行者与校验值，再按 macOS 提供的正常允许打开流程处理。系统没有提供允许选项时，联系发行者取得签名、公证后的版本。

可在「终端」校验下载文件；将路径替换为实际文件：

```sh
shasum -a 256 "$HOME/Downloads/Ancher-Scripter-1.0.0-beta.3-mac-arm64.dmg"
```

### 2.3 Windows 安装

1. 在「设置 → 系统 → 系统信息」确认电脑为 x64 系统。
2. 运行 `Ancher-Scripter-1.0.0-beta.3-win-x64-setup.exe`。
3. 按安装向导选择目录和快捷方式，安装结束后启动应用。
4. 若系统拦截，核对来源、签名和校验值，按系统正常提示处理；没有允许选项时，请发行者提供签名版本。

在 PowerShell 中校验下载文件：

```powershell
Get-FileHash "$env:USERPROFILE\Downloads\Ancher-Scripter-1.0.0-beta.3-win-x64-setup.exe" -Algorithm SHA256
```

### 2.4 激活与首次运行

1. 在激活页复制以 `AS-` 开头的机器码，提供给发行者。
2. 收到以 `AIS1-` 开头的激活码后，粘贴到「手动激活」并激活。不同电脑需要分别签发。
3. 进入「设置 → 模型与密钥」，填写 Ancher API key，点击验证并保存。账号需完成 Ancher 要求的激活，且有可用额度。
4. 如需视频转写，选择相应 Gemini 服务，填写其 API key，验证并保存。Google Cloud 模式这里接收 API key，不接收服务账号 JSON 或 OAuth access token。
5. 返回首页，新建项目；或者导入已有 `.scripter` 项目文件。
6. 先手动输入几行文字，确认编辑和保存；再发一个简短 AI 请求，确认模型连接。

日常编辑和本地项目保存可离线进行；AI 功能需要访问相应服务。API key 在本机经系统加密后保存。不要把密钥写入项目正文或分享的截图。

## 4. macOS：从一台新电脑准备环境

### 4.1 安装 Git 和命令行工具

打开「应用程序 → 实用工具 → 终端」，执行：

```sh
xcode-select --install
```

按弹窗安装 Apple Command Line Tools。它提供 Git 和常见编译工具，通常无需安装完整 Xcode。若提示已安装，继续下一步。

```sh
git --version
curl --version
uname -m
```

`uname -m` 显示 `arm64` 为 Apple 芯片，`x86_64` 为 Intel 环境。Apple 芯片电脑优先使用原生 arm64 的 Node 和工具，避免混用 Rosetta 下的 x64 依赖。

### 4.2 安装 Node.js 24 与 pnpm

1. 打开 [Node.js 官方下载页](https://nodejs.org/en/download)。选择 **24.x LTS** 和 macOS 安装器，按向导安装。
2. 关闭并重新打开终端，使 PATH 生效。
3. 验证：

```sh
node --version
npm --version
node -p "process.platform + '-' + process.arch"
```

期望 Node 显示 `v24.x.x`，平台显示 `darwin-arm64` 或 `darwin-x64`。

使用当前用户目录安装 pnpm，避免给项目依赖安装加 `sudo`：

```sh
npm install --global --prefix "$HOME/.local" pnpm@11.7.0
export PATH="$HOME/.local/bin:$PATH"
pnpm --version
```

期望显示 `11.7.0`。为了新终端也能找到 pnpm，可执行一次以下命令：

```sh
printf '\nexport PATH="$HOME/.local/bin:$PATH"\n' >> "$HOME/.zshrc"
```

如果已经通过版本管理器安装 Node，并能正常安装全局包，也可直接用 `npm install --global pnpm@11.7.0`。无需同时安装多个 pnpm。

### 4.3 获取源码

```sh
mkdir -p "$HOME/Developer"
cd "$HOME/Developer"
git clone https://github.com/ziyeprompttheworld/aiscript.git
cd aiscript
git status
```

仓库如为私有，需要发行者先授予你的 GitHub 账号访问权限。通过 GitHub 正常认证后再 clone；不要把访问 token 写进共享命令或文档。仅解压一个不带 Git 信息的源码 ZIP 不能直接满足当前构建要求，请优先使用 Git clone。

## 5. Windows：从一台新电脑准备环境

### 5.1 安装 Git 与 Node.js

1. 从 [Git 官方下载页](https://git-scm.com/downloads) 下载并安装 Git for Windows。安装时允许命令行和第三方程序使用 Git。
2. 从 [Node.js 官方下载页](https://nodejs.org/en/download) 下载 **24.x LTS、Windows x64 的 `.msi`**，按向导安装并保留添加 PATH 的选项。
3. 完成后关闭旧终端，重新打开 PowerShell。日常运行不需要管理员身份。
4. 验证：

```powershell
git --version
node --version
npm.cmd --version
curl.exe --version
node -p "process.platform + '-' + process.arch"
```

期望平台显示 `win32-x64`，Node 显示 `v24.x.x`。若 `curl.exe` 不存在，先通过 Windows 更新或 [curl 官方 Windows 下载页](https://curl.se/windows/) 安装并加入 PATH，再继续 YouTube 工具准备。

### 5.2 安装 pnpm

```powershell
npm.cmd install --global pnpm@11.7.0
pnpm.cmd --version
```

期望显示 `11.7.0`。下文的 `pnpm` 命令在 PowerShell 中都可以写成 `pnpm.cmd`，避免 `.ps1` 执行策略限制，无需全局放宽执行策略。

若提示命令不存在，重新打开终端；仍失败时检查用户环境变量 PATH 是否包含 npm 的全局命令目录（通常为 `%APPDATA%\npm`）：

```powershell
npm.cmd config get prefix
Get-Command node
Get-Command pnpm.cmd
```

### 5.3 获取源码

选择普通用户有写权限、较短的目录：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\Developer" | Out-Null
Set-Location "$env:USERPROFILE\Developer"
git clone https://github.com/ziyeprompttheworld/aiscript.git
Set-Location aiscript
git status
```

私有仓库需要先取得访问权限并完成 GitHub 认证。若安装失败明确指向原生模块编译缺少工具，再安装 [Visual Studio Build Tools](https://visualstudio.microsoft.com/downloads/) 的「使用 C++ 的桌面开发」工作负载和 Windows SDK，以及该模块要求的 Python 3，并按错误提示重新安装。当前常规路径使用预编译依赖，Python 和 C++ 工具链不是每位客户的必装项。

## 6. 安装项目依赖并首次启动

此节两种系统共用；Windows PowerShell 将 `pnpm` 写为 `pnpm.cmd` 即可。

### 6.1 检查目录和版本

当前目录应包含 `package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`、`apps/` 和 `packages/`。

```sh
git rev-parse --show-toplevel
node --version
pnpm --version
```

### 6.2 一次安装全部工作区依赖

```sh
pnpm install --frozen-lockfile
```

这一步会安装所有工作区依赖并准备 Electron、esbuild 和 FFmpeg。首次下载可能耗时较长，需要能访问 npm、GitHub 和相关二进制下载地址。

仓库 `pnpm-workspace.yaml` 已声明所需的依赖构建许可：`electron`、`esbuild`、`ffmpeg-static`；另外明确禁止 `electron-winstaller`、`tldjs` 的安装脚本。沿用仓库配置，不要关闭全部安装脚本，也不要给所有包无条件批准脚本。

### 6.3 准备 YouTube 工具

```sh
node apps/desktop/scripts/pack-youtube.cjs
```

脚本为当前系统和架构下载并校验 **yt-dlp 2026.08.19**、**Deno 2.9.7**，放在 `apps/desktop/buildres/youtube/<平台-架构>/`。成功时显示 `YouTube tools ready`。这是独立可执行文件，不依赖 Python，也不需要全局安装 yt-dlp 或 Deno。

开发模式的 FFmpeg 来自第 6.2 节安装的 `ffmpeg-static`；打包时会按目标架构重新准备 FFmpeg。不要把上述缓存目录当作源码提交。

### 6.4 检查授权公钥

仓库应已有 `apps/desktop/resources/license-public.pem`。公钥可以交付；签发私钥只能留在发行者电脑上。

macOS：

```sh
test -s apps/desktop/resources/license-public.pem && echo "授权公钥存在"
```

Windows PowerShell：

```powershell
Get-Item apps/desktop/resources/license-public.pem
```

缺失或文件为空时，向发行者取得与激活码匹配的正式公钥，再放到这个位置。客户不要自行生成新密钥替换公钥，否则发行者提供的激活码会不匹配。

### 6.5 检查、构建、启动

```sh
pnpm typecheck
pnpm test
pnpm --filter @scripter/desktop build
pnpm dev
```

最后一个命令会打开 Electron 客户端，并保持终端中的开发进程运行。关闭终端或按 `Ctrl+C` 会停止开发服务。以后每次开发启动只需进入仓库执行 `pnpm dev`，不用重复安装依赖。

首次出现激活页时，按第 2.4 节取得机器码对应的激活码，随后配置 Ancher / Gemini key。开发版和安装包的用户数据位置可能不同；在一种模式激活后，另一种模式如再次要求激活，请按其页面处理。

## 7. 各功能需要什么配置，以及怎样验证

| 功能 | 需要的额外配置 | 验证方法 |
| --- | --- | --- |
| 本地写作、项目笔记、导出 | 客户端激活 | 新建项目、输入文字、重新打开、导出 |
| AI 生成剧本 / 大纲 / 分镜 / 节拍 | Ancher key、网络和额度 | 发一个简短生成请求，检查目标文档实际变化 |
| Ancher 笔记 / 合集 | 与官网账号对应的 Ancher key | 知识库切到「Ancher 笔记」，点击刷新 |
| 本地素材编辑 | 无额外服务 | 知识库切到「项目笔记」，打开原文 |
| 本地音视频转写 | Gemini key、网络；FFmpeg 已准备 | 选择短视频执行「视频 → 逐字稿」，检查 TXT 和 SRT |
| YouTube 有可用字幕 | yt-dlp、Deno 和访问 YouTube 的网络 | 使用一个可访问的公开视频链接，检查字幕转写 |
| YouTube 无可用字幕 | 上述工具加 Gemini key | 下载音轨后调用 Gemini 转写 |
| 自动生成转写标题和摘要 | Ancher key | 检查新生成笔记的标题和摘要；元数据失败不会丢弃已完成的转写 |

YouTube 若要求登录验证，可在客户端选择已经登录的浏览器，按提示允许读取登录信息；也可以下载有权使用的本地视频再转写。浏览器仅在这个场景需要，不是基本运行依赖。

Ancher 负责 AI 内容生成，Mastra 在客户端进程里组织工作流，本地代码负责校验、预览、写入和保存。无需另行启动 Mastra 服务器。

写作时，人手输入文字自动播放打字机音效；AI 写入不会播放。声音大小在设置中调整，系统静音也会影响听感。

### 7.1 开发者进一步验证

在完成 build 后，可单独运行重点集成测试：

```sh
pnpm --filter @scripter/desktop exec node e2e/note-chat.e2e.ts
pnpm --filter @scripter/desktop exec node e2e/new-note.e2e.ts
pnpm --filter @scripter/desktop exec node e2e/typewriter.e2e.ts
pnpm --filter @scripter/desktop exec node e2e/writing-documents.e2e.ts
pnpm --filter @scripter/desktop exec node e2e/mastra-episode.e2e.ts
pnpm --filter @scripter/desktop exec node e2e/topics-artifacts.e2e.ts

```

这些测试使用隔离的临时用户数据和模拟服务，并会启动 Electron 窗口。测试通过证明客户端逻辑符合测试场景，不代表真实账号的额度、网络和服务权限已验证。完整客户验收还要在实际电脑上完成。

## 8. 路线 C：制作独立安装包

普通客户做到第 2 节即可；从源码使用做到第 6 节即可。本节面向需要交付安装包的发行者。

### 8.1 沿用正式授权密钥

已有客户授权时，继续使用现有 `license-public.pem` 以及它对应的签发私钥。私钥不要放入仓库、安装包或交付文件。客户安装后提供本机机器码，发行者在自己的电脑上签发：

```sh
pnpm license issue --machine AS-XXXX-XXXX-XXXX-XXXX --customer "客户名称" --seat 1/3
```

上面的机器码是占位符，必须换为实际机器码；席位也按实际授权填写。

只有一个从未签发过授权的独立新发行项目，才需要首次执行 `pnpm license keypair`，然后把生成的公钥复制到打包资源目录。现有项目更新不执行 `keypair --force`；换签发密钥会使旧激活码无法通过新公钥校验。详见[发行者说明](发行者说明.md)。

### 8.2 打包命令

在对应系统上运行：

```sh
# 本机目录包，用于试装
pnpm --filter @scripter/desktop package:dir

# macOS 上制作 macOS 安装包
pnpm --filter @scripter/desktop dist:mac

# Windows 上制作 Windows 安装包
pnpm --filter @scripter/desktop dist:win
```

不要依次执行两个平台的 dist 命令；选择当前平台对应的一条。产物位于 `apps/desktop/release/`。macOS 配置生成 arm64、x64 的 DMG 和 ZIP；Windows 配置生成 x64 NSIS 安装器。打包 hook 会下载对应目标架构的 FFmpeg、yt-dlp 和 Deno，并附带上游许可证。

对于仅供本机开发验证的未配置证书包，可明确关闭自动发现签名身份。例如 macOS：

```sh
pnpm --filter @scripter/desktop build
CSC_IDENTITY_AUTO_DISCOVERY=false pnpm --filter @scripter/desktop exec electron-builder --dir --mac --arm64 -c.mac.identity=-
```

这不是正式签名、公证流程。正式客户交付需要由发行者配置 Apple Developer ID 签名/公证，或 Windows 签名；签名结果和三个目标平台的启动验证以实际交付记录为准。

### 8.3 在线激活与自动更新

需要在线激活时，在构建前配置 `KEYGEN_ACCOUNT_ID`、`KEYGEN_VERIFY_KEY`。没有配置时使用手动激活。只有发行者需要维护这些构建配置，客户无需安装 Keygen SDK 或配置服务。

当前 beta 默认手动更新。即使依赖中有 electron-updater，也不表示当前包开启自动更新；自动更新由构建配置及可用的更新源共同决定。

## 9. 运行、备份和升级

### 9.1 项目保存在哪里

应用通过 Electron 的 `userData` 目录保存项目、设置和加密凭据。具体路径可在设置里的本地数据功能查看，以客户端实际显示为准。项目数据不在源码目录，替换应用程序文件通常不会删除项目。

迁移电脑前使用「导出 → 整个项目」生成 `.scripter` 备份，并把备份复制到另一处保存。新电脑导入项目后仍需要单独激活、配置 API key；项目备份不是密钥或客户端授权的替代品。

### 9.2 安装包升级

1. 导出重要项目。
2. 保存当前工作并退出应用，等待 AI 请求或转写结束。
3. 用发行者提供的新版安装包覆盖安装。
4. 打开新版，确认激活、项目笔记和剧本内容正常。

不要通过删除用户数据目录来更新。Windows 安装器配置为卸载不删除应用数据，但仍应先备份。

### 9.3 源码升级

先确认本地没有需要保留的未提交修改，再执行：

```sh
git status
git pull --ff-only
pnpm install --frozen-lockfile
node apps/desktop/scripts/pack-youtube.cjs
pnpm typecheck
pnpm --filter @scripter/desktop build
pnpm dev
```

若 `git pull --ff-only` 因本地改动或分支分叉失败，先保留并处理自己的修改，不要通过强制重置丢弃工作。

## 10. 常见问题与排查顺序

| 现象 | 检查与处理 |
| --- | --- |
| `node` / `git` / `pnpm` 命令不存在 | 确认安装完成，重新打开终端，检查 PATH；Windows 尝试 `pnpm.cmd` |
| Node 版本太低、不能运行 `.ts` 或 SQLite | 安装并切换到 Node 24.x，重新确认 `node --version` |
| 锁文件不匹配 | 确认源码和 `pnpm-lock.yaml` 来自同一个版本，使用 pnpm 11.7.0；不要直接删除锁文件 |
| Git 报 `not a git repository` | 用 Git clone 获取仓库，并在仓库根目录构建 |
| Electron 缺失或 FFmpeg 缺失 | 检查安装日志、网络和构建脚本许可；执行 `pnpm rebuild electron esbuild ffmpeg-static` 后再 build |
| YouTube 提示缺少下载工具 | 源码模式重跑 `node apps/desktop/scripts/pack-youtube.cjs`；安装包模式联系发行者更新 |
| YouTube 工具下载超时或校验失败 | 检查 GitHub 连通性、代理和 `curl`；重跑脚本，保留校验，不跳过哈希检查 |
| 代理环境下无法下载 | 在当前终端配置组织提供的 `HTTPS_PROXY` / `HTTP_PROXY`，重试；Electron 的代理方式另见官方安装文档 |
| PowerShell 不允许执行 `.ps1` | 使用 `npm.cmd`、`pnpm.cmd` 执行同样命令 |
| Ancher 连接失败 | 检查 key、账号激活、额度、网络；客户端激活码不能填在 API key 栏 |
| Gemini 403 | 确认服务类型和 key 对应，检查 API 权限、账号配置 |
| Gemini 429 | 检查额度、配额或限流，等待后再试 |
| 转写成功但标题还是文件名 | 检查 Ancher 连接；元数据生成失败会保留 TXT / SRT，可手动修改标题和摘要 |
| 激活码校验失败 | 检查复制是否完整、是否属于本机、包内公钥是否对应；请发行者重新核对 |
| 更新后找不到笔记 | 先确认打开的是同一个项目，知识库里选择「项目笔记」；官网内容在「Ancher 笔记」 |
| macOS 打包提示签名身份有歧义 | 发行者指定唯一证书身份；本机测试可使用第 8.2 节的明确无正式签名方式 |
| macOS 包启动报 Team ID / Library Validation | 发行者检查应用、Framework 和所有原生动态库是否使用一致的签名身份，重新打包；不要让客户关闭系统校验 |
| 窗口没打开、启动后马上退出 | 记录系统版本、芯片架构、客户端版本、完整终端错误，检查安装包是否匹配平台 |

提交问题时附上操作步骤、错误消息、版本和设置里导出的诊断包；先检查内容，不提交 API key、私钥或不希望共享的项目正文。

## 11. 最终检查清单

- [ ] 授权公钥有效，激活码属于这台电脑。

- [ ] 已导出一份完整项目备份，并能找到备份文件。
